# Лабораторна робота №4 — JUnit. JSON

Гілка `lb4` містить лабораторну №4 на основі готової попередньої роботи, включно зі Swing-інтерфейсом.
Використано існуючі моделі й Creator-контролери. Збережено структуру GitHub:
`main/java` і `test/java`; ці шляхи явно налаштовано у Maven. Пакет `ua.example.LR4`
узгоджено з назвою лабораторної №4. Усі імпорти, шляхи й налаштування запуску оновлено.

## Збірка й запуск

Для збірки потрібен **JDK 8+**, змінна `JAVA_HOME` має вказувати на JDK.
Для готового JAR достатньо Java 8+. Maven Wrapper автоматично завантажує
Maven 3.9.9; перша збірка потребує інтернету.

```powershell
.\mvnw.cmd clean verify
java -jar target/java-labs-0-4-1.0-SNAPSHOT.jar
```

На Linux/macOS: `./mvnw clean verify`. За наявності Maven у PATH:
`mvn clean verify` і `mvn exec:java`. GUI запускає клас `ua.example.LR4.Run`.
JAR містить Gson, окремий classpath для запуску не потрібен.

У цьому Windows-профілі символ `^` у шляхах JDK/TEMP заважає Surefire запустити
окрему JVM. Перевірена команда обходу, яка виконує всі тести у процесі Maven:

```powershell
$env:JAVA_HOME = Join-Path $env:USERPROFILE '.jdks/openjdk-25'
.\mvnw.cmd '-DforkCount=0' clean verify
java -jar target/java-labs-0-4-1.0-SNAPSHOT.jar
```

Проєкт за замовчуванням запускає тести в окремій JVM. Окремо всі тести успішно
виконані у JVM Java 8 з локальними шляхами JDK/TEMP без спеціальних символів.
У `mvnw.cmd` шлях до Maven взято в лапки для підтримки спеціальних символів і пробілів.

В IntelliJ IDEA відкрийте кореневий `pom.xml` як Maven-проєкт, виконайте Reload
All Maven Projects та встановіть Project SDK. Maven позначить `main/java` як
Sources, а `test/java` як Tests. Потім запускайте `ua.example.LR4.Run` та JUnit-тести.

У проєкті є два пакети моделі: `ua.example.LR4.model` для Swing та
`ua.example.LR3.model` для консольної версії. Обидва збережено; нових дублікатів
немає. У старому `NamedUnit.equals` усунуто несиметричне порівняння різних типів
підрозділів. Нові можливості додано до пакета GUI — `ua.example.LR4`.

## JsonManager і рівність

`JsonManager` у пакеті `persistence` відділяє JSON від моделі й представлення:

| Метод | Призначення |
|---|---|
| `toJson(University)` | Серіалізація у читабельний JSON-рядок |
| `fromJson(String)` | Відновлення University з рядка |
| `saveToFile(University, Path)` | Запис JSON у файл UTF-8 |
| `loadFromFile(Path)` | Читання файла UTF-8 і відновлення University |

Gson-адаптери використовують існуючі конструктори, зберігаючи перевірки обов'язкових
полів і колекцій. Некоректні дані спричиняють `JsonParseException`, файлові помилки —
`IOException`. Поле `kind` (`human`/`student`) зберігає тип людини, зокрема студента-
старости у полі `Group.head`, оголошеному як `Human`. JSON, записаний програмою,
містить цей маркер. Відновлюються рівні дані, а не ідентичність посилань (`==`).

Збереження спочатку записує JSON у тимчасовий файл поруч із цільовим, а потім
замінює цільовий файл атомарним переміщенням. Якщо файлова система не підтримує
атомарне переміщення, використовується звичайна заміна. Тимчасовий файл прибирається
і після помилки; каталог не може бути перезаписаний замість JSON-файла.

`Human.equals/hashCode` враховують тип, ПІБ і стать; `Student` успадковує їх,
оскільки додаткових полів не має. `NamedUnit` враховує тип, назву й керівника.
University, Faculty, Department і Group також порівнюють вкладені списки.
Порядок елементів враховується. `Sex` використовує стандартну рівність enum.

## Графічний інтерфейс

Збережено дерево, панель відомостей, створення університету, розгортання,
згортання, інформацію та вихід. Додано рядок кнопок того самого оформлення:

- **Зберегти JSON**: вибір файла, додавання `.json`, підтвердження перезапису.
- **Завантажити JSON**: відновлення й показ дерева; помилка не змінює поточні дані.
- **Перевірити рівність**: показ `equals = true/false` для початкового/останнього
  збереженого університету та завантаженого. Доступна після завантаження.

Створення задає початковий незалежний знімок даних. Успішне збереження оновлює
знімок; невдале його не змінює. Завантаження не змінює знімок, тому можна
порівнювати його з різними файлами. Скасування файлового діалогу не змінює дані.

## Тестування

`UniversityJsonTest` використовує існуючий `Run.createTypycalUniversity()` →
`UniversityCreator`. Ієрархія: **2 факультети × 2 кафедри × 2 групи × 2 студенти =
16 студентів**. Тест записує `oldUniversity` у файл JUnit `@TempDir`, читає JSON,
відновлює `newUniversity`, виконує `assertEquals` та явно перевіряє `equals == true`.
JUnit прибирає тимчасові JSON-файли після виконання.

Додатково перевіряються UTF-8, hashCode, симетричність і транзитивність рівності,
зміни на всіх рівнях ієрархії, тип старости, незмінювані представлення колекцій,
порожня ієрархія, екранування тексту, некоректний JSON і помилки файлів.

`UniversityGuiTest` запускає незмінений `UniversityVerification` лабораторної №3
та перевіряє нові кнопки на EDT. У тестах підмінено вибір шляху й повідомлення;
запис, читання, дерево, порівняння та обробники кнопок — справжні.
Без графічного середовища два Swing-тести явно пропускаються.

Під час повторної перевірки відновлено файли попередніх лабораторних, які були
порожніми у робочій копії. У лабораторній №2 виправлено геометричне середнє:
нуль перед від'ємним числом більше не приховує помилковий від'ємний елемент.
`PreviousLabsTest` перевіряє цей випадок, статистику матриці й стару консольну ієрархію.

Результат: **41 тест, 0 невдач, 0 помилок, 0 пропусків; BUILD SUCCESS**.
Перевірено JDK 25 і окрему JVM Java 8. Звіти: `target/surefire-reports/`.
Swing-зображення оформлення: `target/gui-preview.png`. Системне захоплення екрана
повертало тайм-аут, тому повна ручна перевірка файлових діалогів не підтверджена.

## Демонстрація викладачу

1. Покажіть гілку `lb4`, пакет `LR4`, коміт `Lab 4: JSON and JUnit`.
2. Запустіть тести, покажіть `UniversityJsonTest`, `@TempDir` та обидві перевірки рівності.
3. Запустіть GUI; покажіть дерево, відомості студента, згортання й розгортання.
4. Натисніть **Зберегти JSON**, виберіть файл та відкрийте його в редакторі.
5. Натисніть **Завантажити JSON**, виберіть той самий файл і покажіть відновлене дерево.
6. Натисніть **Перевірити рівність** — отримаєте `equals = true`.
7. Змініть назву університету в JSON, завантажте файл повторно без нового збереження
   з GUI — отримаєте `equals = false`.
8. Відкрийте некоректний JSON: програма повідомить про помилку й збереже дерево.
